# 迅投 QMT 极速策略交易系统使用教程与程序化接口说明

> 本文根据用户提供的《迅投QMT极速策略交易系统说明文档》（北京睿智融科控股股份有限公司，2025 年 12 月）整理。
>
> **重要边界**：这份 PDF 主要是 **QMT 交易终端与内置策略系统的使用说明**，并不是完整的 `xtquant.xttrader / xtquant.xtdata` Native Python SDK 参考手册。
> 手册明确披露的程序化能力主要包括：
>
> 1. QMT 内置 Python/VBA 模型与函数交易；
> 2. `passorder` 等交易函数；
> 3. 便捷交易（TXT/CSV 文件协议）；
> 4. 批量预埋单（DBF 文件接口）；
> 5. CSV 预埋单（`signal.*.txt` + CSV 回报文件）；
> 6. Python 策略托管运行；
> 7. 资产/持仓/委托/成交等数据导出；
> 8. Jupyter Notebook 中可调用的一组 QMT API。
>
> 因此，如果目标是把 QMT 接入自建 `broker gateway`，本手册最有价值的部分不是“REST OpenAPI”，而是 **文件协议 + 数据导出 + Python 策略/函数交易**。

# 1. QMT 是什么

迅投 QMT 极速策略交易系统是集以下能力于一体的交易终端：

- 行情显示；
- 投资研究；
- Python/VBA 量化模型；
- 策略回测；
- 模拟运行；
- 实盘策略交易；
- 股票、期货、融资融券、港股通、股票期权、ETF 申赎等交易；
- 组合交易和算法交易；
- 多资金账号管理；
- 多层风控；
- 数据导入导出；
- 外部程序文件式交易接口。

手册对 QMT 的定位并不是单纯的“券商下单软件”，而更接近：

```text
行情终端
  +
策略研究/回测
  +
策略运行容器
  +
交易执行终端
  +
风控系统
  +
文件式外部交易接口
```

# 2. 安装、登录与基础配置

## 2.1 手册给出的基础运行环境

手册列出的基线配置为：

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 64-bit |
| CPU | Intel Core i7-7770 或更高 |
| 显卡 | Intel HD Graphics 4400 |
| 内存 | 8 GB RAM |
| 磁盘 | SSD，200 GB 可用 |
| 网络 | 10 Mbps 及以上 |
| 分辨率 | 1920×1080 |

这些是手册给出的产品运行基线，并不是现代量化工作站的推荐上限。

## 2.2 行情源配置

进入通信设置后，可以配置行情主站和交易中心。

两者含义：

- **行情主站**：行情界面的行情来源；
- **交易中心**：交易界面盘口行情来源。

常见选项：

- 交易中心自动更换服务器；
- 断线弹出窗口；
- 自动优选；
- 自动隐藏。

实际使用时建议首先确认：

```text
行情连接正常
交易中心连接正常
账户登录正常
交易服务器正常
```

否则策略和文件接口即使生成订单，也可能无法正常执行。

## 2.3 登录模式

终端支持：

- 行情 + 交易；
- 交易；
- 独立行情；
- 独立交易。

资金账号登录模式需要该资金账号已经添加到管理端账号白名单。

# 3. 账号管理

首次使用交易模块时，需要先添加资金账号。

可以通过：

```text
交易模块 -> 添加账号
```

或：

```text
系统设置 -> 账号管理
```

完成添加。

## 3.1 添加账号需要的信息

通常包括：

- 账号类型；
- 交易平台；
- 经纪公司；
- 资金账号；
- 密码。

## 3.2 白名单机制

如果系统开启账号白名单：

1. 账号必须先在 QMT 管理终端白名单中；
2. 交易端显示待校验账号；
3. 输入密码进行登录校验；
4. 校验成功后才能正常使用。

如果没有相应权限，很多程序化功能不会显示或无法启动。

因此进行 API/自动化接入前，应先确认：

```text
[ ] 资金账号已加入白名单
[ ] 账号登录校验通过
[ ] 对应交易业务已开通
[ ] 便捷交易权限已开通（如使用）
[ ] 批量预埋单权限已开通（如使用）
[ ] Python 策略权限已开通（如使用）
```

# 5. 手工交易模块

股票交易下单面板可以进行：

- 买入；
- 卖出；
- 市价交易；
- 逆回购；
- 新股/新债申购；
- 可转债；
- 科创板；
- 创业板；
- 大宗交易等。

## 5.1 股票基本规则

按手册说明：

- 一般股票最小交易单位：100 股；
- 股票采用 T+1；
- 债券最小交易单位：10 的整数倍；
- 手册描述债券采用 T+0。

程序化接口生成委托数量时，不能只做：

```python
qty = int(target_value / price)
```

而必须再执行对应市场的交易单位约束。

## 5.2 多账号分单

QMT 支持三种典型多账户分配：

### 平均分配

例如：

```text
总量 = 300 股
账户数 = 3

=> 每个账户 100 股
```

### 交易权重

例如：

```text
A 权重 = 2
B 权重 = 1
总量 = 300

=> A = 200
=> B = 100
```

### 可用比例

按各账号可用资金比例分配。

# 7. 从回测到模拟再到实盘

这是实盘前最重要的流程。

推荐严格遵循：

```text
策略编写
   ↓
编译
   ↓
历史回测
   ↓
模拟运行
   ↓
检查信号
   ↓
检查委托生成逻辑
   ↓
小资金实盘
   ↓
正式实盘
```

## 7.1 模拟运行

模型编辑器中点击：

```text
运行
```

进入模拟运行。

手册明确：

> 模拟运行状态不进行任何实盘交易操作。

## 7.2 模型交易

进入：

```text
模型交易
```

可运行：

- 增强策略；
- Python 策略；
- VBA 策略。

## 7.3 实盘和模拟的区别

两种模式都会生成：

- 策略信号；
- 日志；
- 委托逻辑。

区别是：

```text
模拟：不向柜台发送交易信号
实盘：向柜台发送实盘交易信号
```

因此在自动化部署时必须把：

```text
strategy enabled
```

和：

```text
live trading enabled
```

当成两个独立状态管理。

# 8. QMT 程序化接口总览

从本手册可以归纳出 6 条主要程序化路径：

| 接口 | 调用方 | 执行方式 | 是否适合外部 Broker Gateway |
|---|---|---|---|
| Python/VBA 模型 | QMT 内部 | 模型运行 | 中等 |
| 函数交易 | QMT 内部 | `passorder` 等 | 中等 |
| 便捷交易 | 外部程序 | TXT/CSV 文件 | 高 |
| 批量预埋单 | 外部程序 | DBF 文件 | 很高 |
| CSV 预埋单 | 外部程序 | TXT + CSV | 很高 |
| 数据导出 | QMT -> 外部 | DBF/TXT/CSV | 很高 |
| Jupyter API | QMT 内部 Notebook | Python 函数 | 研究用途高 |

可以把它理解为：

```text
                 ┌─ 内置 Python 模型
                 ├─ 函数交易
QMT 程序化能力 ──┼─ 便捷交易文件协议
                 ├─ DBF 批量预埋
                 ├─ CSV 预埋
                 ├─ 数据导出
                 └─ Jupyter API
```

# 10. 便捷交易文件协议

这是手册中最简单的外部交易接口。

入口：

```text
独立交易
 -> 策略交易
 -> 便捷交易
```

## 10.1 工作机制

外部程序和 QMT 通过中间文件通讯。

流程：

```text
外部程序生成协议文件
        ↓
QMT 扫描目录
        ↓
发现文件
        ↓
读取指令
        ↓
删除源文件
        ↓
生成交易任务
        ↓
柜台
```

手册说明 QMT 大约每 **1 ms** 扫描一次文件路径。

因此不要把这个目录当普通日志目录使用。

## 10.2 协议字段

TXT 示例协议参数顺序为：

```text
下单类型,
通道号,
交易市场,
交易代码,
交易数量,
报价类型,
交易价格,
投资备注(可选)
```

即逻辑形式：

```text
order_type,
channel,
market,
code,
volume,
price_type,
price,
note
```

## 10.3 股票/信用下单类型

| 代码 | 含义 |
|---:|---|
| 23 | 股票买入 / 两融担保品买入 |

# 16. 权限、风控与实盘安全

这是自动交易最容易被忽略的一层。

## 16.1 账号风控

QMT 账号风控包括：

- 黑白名单；
- 交易限制；
- 资产组合风控；
- 个股限制；
- 交易所合规。

## 16.2 黑白名单

黑名单：

```text
禁止交易
```

白名单：

```text
允许交易
```

如果没有设置黑白名单，手册说明默认证券均按白名单处理。

还可以设置：

```text
不限制卖出/平仓
```

即：

- 黑名单股票仍可卖出；
- 黑名单期货仍可平仓。

这是生产系统非常重要的“只许减仓”能力。

## 16.3 交易限制

可以限制：

- 市价单；
- 涨停价；
- 跌停价；
- 与最新价偏离比例；
- 与昨收偏离比例；
- 单笔最大委托量；
- 单笔最大金额；
- 禁止涨停卖出；
- 禁止跌停买入。

程序化系统必须把 QMT 风控当作：

```text
最终 Broker-side Risk Gate
```

而不是认为上游策略已经做了风控就可以关闭终端风控。

## 16.4 本地超限拦截

系统设置还支持：

```text
启用单笔委托量超限本地拦截
```

以及自动拆单提示等。

# 17. 面向 Broker Gateway 的推荐接入架构

> 本章是基于手册能力给出的工程实现建议，不是手册原文。

如果目标是：

```text
qlib / Lean / 自研策略
       ↓
Broker Gateway
       ↓
国泰海通 QMT
       ↓
交易柜台
```

不建议一开始直接把 QMT 客户端内部 Python 逻辑和策略平台强耦合。

推荐拆成：

```text
┌──────────────────────────────┐
│ Strategy / Qlib / Lean       │
└──────────────┬───────────────┘
               │
               │ REST / RPC
               ▼
┌──────────────────────────────┐
│ Broker Gateway               │
│                              │
│ Order Manager                │
│ Risk Manager                 │
│ Reconciliation              │
│ Idempotency                  │
└───────┬──────────────┬───────┘
        │              ▲
        │ Write        │ Read
        ▼              │
┌─────────────┐  ┌──────────────┐
│ signal/DBF  │  │ CSV/DBF导出  │
│ 下单/撤单   │  │ 资金持仓成交 │
└──────┬──────┘  └──────▲───────┘
       │                │
       ▼                │
┌──────────────────────────────┐
│ 国泰海通 QMT                 │
│ 风控 + 交易服务              │
└──────────────┬───────────────┘
               ▼
             柜台
```

## 17.1 推荐优先级

### 第一选择：CSV 预埋 + 数据导出

优点：

- 文本文件容易调试；
- 外部程序容易实现；
- 委托/失败/成交/持仓/资产文件齐全；
- 适合 Python Broker Gateway；
- 日期文件可防止历史订单误执行。

### 第二选择：DBF 批量预埋 + DBF 数据导出

优点：

- 接口结构更明确；
- 支持反馈文件；
- 适合大量订单；
- 支持较丰富的业务类型。

缺点：

- DBF 处理复杂度高于 CSV；
- 需要注意文件锁和增量更新。

### 第三选择：便捷交易

适合：

- 初期 Smoke Test；
- 少量订单；
- 验证实盘链路。

不适合作为长期大型 OMS 的唯一接口。

---

# 17.2 Gateway 建议定义的统一接口

上层不要暴露 QMT 的文件细节。

建议定义：

```text
GET  /v1/account
GET  /v1/positions
GET  /v1/orders
GET  /v1/fills

POST /v1/orders
POST /v1/orders/{id}/cancel
```

Gateway 内部再转 QMT 文件。

## 17.3 统一订单结构

例如：

```json
{
  "client_order_id": "qlib-20260812-000001",
  "account_id": "xxxx",
  "instrument": "SH600000",
  "side": "BUY",
  "quantity": 100,
  "order_type": "LIMIT",
  "limit_price": 10.50,
  "strategy": "qlib_lgbm_v1"
}
```

再映射成：

```text
QMT order_type
QMT price_type
QMT market
QMT account
QMT strategy
QMT note
```

# 17.4 用 `strategy` / `note` 保存客户端订单号

DBF 接口支持：

```text
strategy
note
```

CSV 接口支持：

```text
投资备注
策略名称
```

建议把外部系统订单 ID 写进去：

```text
note = qlib-20260812-000001
```

这样订单全链路可以做：

```text
client_order_id
      ↓
QMT note
      ↓
QMT order
      ↓
QMT deal
      ↓
Gateway reconciliation
```

# 17.5 文件写入必须原子化

手册说明 QMT 的扫描周期可以达到毫秒级，而且便捷交易读取后会删除源文件。

因此外部程序不要这样直接写：

```python
open("signal.xxx.txt", "w")
write(part1)
write(part2)
close()
```

否则 QMT 可能在文件尚未完整时读取。

建议：

```text
先写临时文件
     ↓
flush
     ↓
fsync
     ↓
atomic rename
     ↓
正式 signal 文件
```

例如：

```python
tmp = "signal.xxx.tmp"
final = "signal.xxx.txt"

write(tmp)
fsync(tmp)
os.replace(tmp, final)
```

---

# 17.6 防重复下单

必须实现幂等。

建议每个订单有唯一：

```text
client_order_id
```

Gateway 本地保存：

```text
client_order_id
QMT_ORDERID
QMT_ORDERSYSID
state
created_at
updated_at
```

状态机：

```text
INTENT
  ↓
SUBMITTED
  ↓
ACKNOWLEDGED
  ↓
PARTIALLY_FILLED
  ↓
FILLED
```

另外：

```text
CANCELLED
REJECTED
```

---

# 17.7 不要把“文件已消失”当作“订单已成交”

便捷交易读取后会删除源文件。

因此：

```text
文件消失
```

只能说明：

```text
QMT 已读取
```

不能说明：

```text
柜台已接受
更不能说明
已经成交
```

必须继续读取：

```text
order
order_error
deal
```

进行确认。

# 18. 实盘联调步骤

推荐按以下顺序。

## Phase 0：客户端确认

```text
[ ] QMT 正常登录
[ ] 账号正常
[ ] 行情正常
[ ] 交易服务器正常
[ ] 手工买卖正常
```

## Phase 1：只读

开启数据导出。

只读取：

```text
asset
position
order
deal
```

验证 Gateway 和 QMT 数据一致。

暂时禁止自动下单。

## Phase 2：最小委托

使用：

```text
便捷交易
```

发送 1 笔最小数量委托。

验证：

```text
signal
 -> QMT任务
 -> 委托
 -> order
 -> 成交
 -> deal
 -> position
 -> asset
```

## Phase 3：撤单

发一笔不容易立即成交的限价单。

验证：

```text
submit
 -> ACK
 -> cancel
 -> CANCELLED
```

## Phase 4：部分成交

测试：

```text
PARTIALLY_FILLED
```

避免 OMS 将部分成交误认为完整成交。

## Phase 5：CSV 预埋

切换：

```text
CSV 预埋
```

验证：

```text
order
order_error
cancel_error
deal
position
asset
```

## Phase 6：故障恢复

测试：

- Gateway 重启；
- QMT 重启；
- 网络断开；
- 文件重复；
- 订单已报但 Gateway 没收到；
- QMT 返回而 Gateway 未处理；
- 交易日切换。

## Phase 7：Shadow Mode

连续运行若干交易日：

```text
策略产生订单
但不真实发送
```

将计划订单与人工/QMT 实盘状态进行比对。

## Phase 8：小资金实盘

最后才启用：

```text
真实 POST /orders
```

# 19. 常见错误与排查

## 19.1 Python 模型无行情数据

检查：

```text
操作 -> 数据管理 -> 补充数据
```

尤其是：

```python
get_market_data(...)
```

使用前。

## 19.2 Python 模型无法运行

检查：

```text
[ ] Python 库是否下载
[ ] Python 路径是否正确
[ ] 是否启用本地 Python
[ ] 第三方包是否有授权
[ ] 模型是否编译成功
```

## 19.3 策略有信号但没有真实委托

检查运行模式：

```text
模拟
还是
实盘
```

模拟模式不会向柜台发单。

## 19.4 外部文件写入后没有执行

检查：

```text
[ ] 功能权限
[ ] 监控是否启动
[ ] 监控目录是否正确
[ ] 文件名是否正确
[ ] 日期是否当天
[ ] 下单文件序号是否重复
[ ] 账号类型是否正确
[ ] 账号是否登录
[ ] 市场代码是否正确
[ ] 字段顺序是否正确
```

## 19.5 CSV 下单失败

读取：

```text
order_error.*
```

## 19.6 CSV 撤单失败

读取：

```text
cancel_error.*
```

## 19.7 DBF 下单结果未知

读取：

```text
*_result.dbf
```

重点字段：

```text
MESSAGE
STATUS
ORDERID
ORDERSYSID
```

## 19.8 同一个订单重复执行

检查：

```text
signal 文件序号
client_order_id
Gateway 幂等表
QMT orderid
QMT ordersysid
```

# 结论

对于普通使用者，QMT 的学习主线是：

```text
登录
 -> 行情
 -> 账号
 -> 手工交易
 -> Python 模型
 -> 回测
 -> 模拟
 -> 实盘
```

对于程序化交易系统开发者，更重要的主线是：

```text
策略平台
      ↓
统一 Broker Gateway
      ↓
QMT CSV/DBF/文件接口
      ↓
QMT 风控
      ↓
券商柜台
```

其中最值得优先掌握的四项能力是：

```text
1. CSV 预埋单
2. DBF 批量预埋单
3. 数据导出
4. Python / 函数交易
```

如果目标是建设长期可维护的实盘交易平台，建议把 QMT 视为：

```text
Broker Execution Adapter
```

而不是把所有策略逻辑直接写进 QMT。

这样策略研究、组合管理、风控、OMS 与具体券商终端之间可以保持清晰边界。
